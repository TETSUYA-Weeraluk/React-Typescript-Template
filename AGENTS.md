# Project Structure (read before adding files)

```
src/
├── main.tsx              # entry: validate env → (dev) start MSW → dynamic import App
├── app/                  # app shell: App providers, router instance, QueryClient factory
├── routes/               # TanStack Router file-based routes — THIN files only (search schema, loader, guard)
│   ├── _public/          # pages without login (layout: AuthLayout)
│   └── _authenticated/   # pages that require login (guard + AppLayout) — new pages go here
├── features/<name>/      # everything for one domain
│   ├── api/              # <name>.api.ts (axios calls) + <name>.queries.ts (query keys, queryOptions, mutation hooks)
│   ├── components/       # components used only by this feature
│   ├── pages/            # page components rendered by route files
│   ├── schemas/          # zod schemas (forms, URL search params)
│   └── types.ts
├── components/
│   ├── ui/               # shadcn generated — add with `pnpm ui:add <name>`, avoid hand edits
│   ├── form/             # TanStack Form field components bound to shadcn (registered in lib/form.ts)
│   ├── data-table/       # DataTable + pagination (TanStack Table)
│   ├── layouts/          # AppLayout, AuthLayout, sidebar, user menu
│   ├── feedback/         # error boundary, route error, not found, page loader
│   └── theme/            # ThemeProvider + mode toggle
├── config/               # env.ts, i18n.ts, navigation.ts
├── hooks/                # shared hooks
├── lib/                  # api-client, api-error, form, format, validation, utils
├── stores/               # zustand stores (auth tokens only)
├── locales/              # th.json, en.json (must have identical keys — tested)
├── mocks/                # MSW handlers for `pnpm dev:mock` and tests
├── test/                 # vitest setup + render helpers
└── types/                # shared types + module augmentation
```

Dependency direction: `routes → features → components/lib/hooks/stores/config`.
Shared folders (`components`, `lib`, `hooks`, `stores`) must NOT import from `features/*`
(exception: `components/layouts` may use `features/auth` hooks). Features should not import each other's internals
except through their `api/*.queries.ts`.

- File names: **kebab-case** (`user-form-dialog.tsx`). Components: PascalCase named exports. No default exports
  except where a library requires it. No barrel `index.ts` files (hurts tree-shaking).
- Types: no `I` prefix (`User`, not `IUser`). Avoid `any`; use `unknown` and narrow.
- Import alias: `@/` = `src/`.

# Core Principles & Readability

- Simplicity over cleverness: straightforward, "boring" code that is easy to read at a glance.
- Early returns (guard clauses) instead of deep nesting.
- Descriptive names (`isLoading`, `handleFormSubmit`, `UserProfileCard`); no confusing abbreviations.
- Small components with a single responsibility. Group related files inside the feature.
- Accessibility: semantic HTML, labels for every input, `aria-label` for icon-only buttons, keyboard support.
- Mobile-first responsive design (`text-sm md:text-base`).

# Routing (TanStack Router)

- New page = new file under `src/routes/_authenticated/` (or `_public/`). `routeTree.gen.ts` is generated by the Vite
  plugin — never edit it by hand; commit it.
- Route files stay thin: `validateSearch` (zod), `loader` (prefetch via `context.queryClient`), `head`, `component`.
  The page UI lives in `features/<name>/pages/`.
- Page components read route data with `getRouteApi('/path')` instead of importing the route file.
- Table/list state (page, search, filters) lives in the URL via `validateSearch`, not in `useState`.
- Navigation: `<Link to="...">` / `navigate({ to })` — paths are type-checked. Add sidebar items in `config/navigation.ts`.

# Data Fetching (TanStack Query)

- All HTTP goes through `apiClient` (`lib/api-client.ts`). API functions return the payload, not `AxiosResponse`.
- Each feature has a key factory (`userKeys`) and `queryOptions` factories; reuse them in loaders, components and
  invalidation. Never hand-write query keys inline.
- Mutations are custom hooks (`useCreateUser`) that invalidate/update the cache in `onSuccess` via `useQueryClient()`.
- API errors are toasted globally by the QueryClient. Pass `meta: { suppressErrorToast: true }` only when the UI
  handles the error itself (e.g. inline form error).
- Use `placeholderData: keepPreviousData` for paginated lists only, not globally.
- Never store server data in zustand. zustand is for client-only state (auth tokens).

# Forms (TanStack Form)

- Exclusively use **TanStack Form** through `useAppForm` from `@/lib/form` — no other form libraries.
- Render fields with `<form.AppField name="x">{(field) => <field.TextField label="..." />}</form.AppField>`.
  Available: TextField, PasswordField, TextareaField, NumberField, SelectField, CheckboxField, SwitchField, and
  `form.SubmitButton` inside `<form.AppForm>`.
- Validate with a zod schema in `features/<name>/schemas/` using messages from `@/lib/validation` (translated).
- New field type: create it in `src/components/form/` using `useFieldContext` from `@/lib/form-context`, then
  register it in `src/lib/form.ts`.

# UI & Styling (shadcn/ui + Tailwind CSS v4)

- Exclusively use **shadcn/ui** for foundational components. **DO NOT use Ant Design or other UI kits.**
- Add components with `pnpm ui:add <component>`; compose them instead of editing `components/ui/*`.
  If an edit is unavoidable, leave a comment saying what changed from the generated version.
- Colors come from the CSS variables in `src/index.css` (`bg-primary`, `text-muted-foreground`, `bg-success`).
  Do not hard-code hex colors; every screen must work in both light and dark mode.
- Icons: `lucide-react` only.

# i18n

- Every user-facing string goes through `t()` from `react-i18next`. Add keys to BOTH `locales/th.json` and
  `locales/en.json` (a test fails if they differ). Dates/numbers: `formatDate`, `formatNumber` from `lib/format.ts`.

# Environment (Vite)

- Use `env` from `@/config/env` (validated) — not `import.meta.env` directly and never `process.env`.
- New variable: add it to `vite-env.d.ts`, validate it in `config/env.ts`, document it in `.env.example`.
- Avoid Next.js specific APIs (`next/image`, `next/link`, server components).

# Error Handling

- Route-level errors render `RouteError` (retry button); `notFound()` from loaders renders `NotFound`.
- Handle API errors with user-friendly messages; never show raw stack traces in production.

# Testing (Vitest + Testing Library + MSW)

- Write tests for logic that is easy to break: utilities in `lib/`, auth/token flows, complex hooks and forms.
  Simple presentational components do not need tests.
- Tests live next to the code (`*.test.ts(x)`). Mock HTTP with MSW (`server.use(...)`), not by mocking axios.
- Use `renderWithProviders` from `@/test/render` for components that need Router/Query.
- Before finishing a task run: `pnpm check` (typecheck + lint + format check + tests).

# Performance

- Routes are code-split automatically (`autoCodeSplitting`). Use `React.lazy` for heavy, rarely used widgets.
- Use `useMemo`/`useCallback` only where it prevents real work (e.g. table columns); don't over-optimize.
- Images: modern formats (WebP/AVIF) and `loading="lazy"`.
